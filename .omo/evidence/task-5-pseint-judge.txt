INTERPRETATION DECISIONS (documented; corpus todo 8 will pin exact behavior)
----------------------------------------------------------------------------
  1. STEP-COUNT AMBIGUITY (SPEC §(g)): the table says "Each operator
     evaluation within an expression costs 1 step" and its example claims
     `a + b * c` costs 3 steps. The literal rule (each operator NODE
     evaluated = 1 step) gives 2 steps for `a + b * c`. We implement the
     LITERAL rule (2 operator steps) and record the discrepancy here; the
     corpus (todo 8) will pin the exact behavior. test_steps_operator_evaluation
     asserts 2 operator steps.
  2. Para step model: entry = 1 step (statement); per iteration = 1 step
     (iteration check) + body steps + 1 step (implicit increment); final
     failing check = 1 step. End/step expressions evaluated once at entry.
     Loop variable type = declared type, else Real if any bound/step is
     Real, else Entero; incremented value converted back to that type.
     Bidirectional: step >= 0 loops while var <= end; step < 0 while var >= end.
  3. Segun: expr evaluated once (must be Entero, else ERR_TYPE); each
     integer case check = 1 step; De Otro Modo has no condition check (0
     steps); cases after the match are not checked.
  4. StringLiteral typing: SPEC §(a) says character literals are
     double-quoted single chars, so a 1-char string literal is typed
     Caracter, multi-char is Cadena.
  5. Cadena->Logico conversion is exact-match ("Verdadero"/"Falso"); Leer
     Logico parsing is case-insensitive per §(f).
  6. Numeric token grammar for Leer/conversion: [+-]?\d+ (Entero) and
     [+-]?\d+\.\d+ (Real) — no exponent notation, matching SPEC §(a)
     literal grammar. int()/float() are NOT used directly for parsing.
  7. Real formatting = repr(float) verbatim (shortest roundtrip). For
     values where repr produces exponent notation (e.g. 1e+20) the repr
     output is used as-is; corpus will pin.
  8. MOD sign convention: Python's % (result non-negative for positive
     divisor). int/int -> real via Python's true division.
  9. ^ (power): int ** int with non-negative exponent -> Entero, else Real.
  10. Conditions must be Logico (no implicit conversion); Segun expr must
      be Entero. String ordering (< > <= >=) allowed lexicographically;
      Logico ordering rejected (only = <> allowed).
  11. Definir/SubProceso definitions count as 1 step each (they are
      statements in the body). Definir with init assigns to the first name.
      Conflicting Definir re-declaration -> ERR_TYPE.
  12. Uninitialized/undefined variable reads -> ERR_TYPE with clear message.
  13. No step budgets / output caps applied (runner-level, todo 7); the
      evaluator only counts. seed param accepted but unused (AZAR is todo 6).
  14. Leer input is line-aware: tokens are \s+-split per line; normal Leer
      consumes tokens across lines (matching global \s+ split); bare Leer
      discards the rest of the current line and moves to the next.
