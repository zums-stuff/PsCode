## D13 normalization pipeline
1. Strip `//` line comments via `re.compile(r"//[^\n]*").sub("", source)`.
2. Lowercase.
3. Fold identifier tokens via `re.sub(r"\b[A-Za-z_]\w*\b", "N", ...)`.
4. Strip all whitespace via `re.sub(r"\s+", "", ...)`.

**Order matters (recorded in evidence because the task brief listed a different
order):** folding MUST happen before whitespace is stripped, otherwise
`\b[A-Za-z_]\w*\b` misses identifiers that become glued to adjacent digits
(e.g. `0Para` after ws-strip has no `\b` boundary between `0` and `P`).
Lowercasing before fold keeps the placeholder `N` uppercase. Comments are
stripped first so a `//` inside a string literal cannot swallow the rest of
the line. The four operations are still applied; only the application order
differs from the task brief.

## Design decisions
- **Canonical ordering for dedupe.** Each emitted pair uses `(min(a,b), max(a,b))`
  so the same pair can never appear twice regardless of submission order. The
  `seen` set is a belt-and-suspenders guard against duplicate inputs (e.g.
  caller passes `[a, a, b]`).
- **Top-k is per submission; union is symmetric.** A pair survives the cap iff
  either side kept the other — this is the natural "top-k per submission" rule
  and makes the API's report stable when many copies share a central source.
- **`exclude_team_pairs`** accepts any iterable of `(id_a, id_b)` tuples; both
  orderings are accepted and stored as `frozenset({a, b})` keys.
- **No DB writes** (pure module); the API layer (todo 39) persists.
- **No AST fingerprints** (user chose minimal text-similarity per D13).
