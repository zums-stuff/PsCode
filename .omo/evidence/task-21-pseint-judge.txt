WHAT WAS BUILT
--------------
New file web/api/src/pseint_api/routes/listings.py — three paginated GET
endpoints, all with the {items, page, size, total} envelope:

1. GET /api/problems?page=1&size=20
   Items: {id, title, expected_complexity, compare_mode, is_solved,
   best_verdict}. is_solved = user has >=1 Run with summary_verdict="AC".
   best_verdict = highest-priority verdict among the user's runs
   (AC > WA > TLE > RE > CE), null when no runs. Per-user state computed
   from ONE aggregate query (select Run.problem_id, Run.summary_verdict
   where user_id = me, verdict not null) grouped in Python — no N+1, no
   per-problem lookup.

2. GET /api/assignments?page=1&size=20
   Items: {id, problem_id, deadline, status, best_verdict, best_steps}.
   status = "open" if now < deadline else "closed". Scoped to the classes
   the user may see (admin: all, teacher: own classes, student:
   ClassMember) — mirrors the pre-existing list_assignments role logic.
   best_verdict/best_steps from the user's runs on that assignment
   (Run.assignment_id == assignment.id), best verdict wins, fewest steps
   breaks ties. One aggregate query for all assignment runs.

3. GET /api/contests?page=1&size=20
   Items: {id, title, start_at, end_at, status, scoring_mode,
   teams_enabled, is_registered}. status = upcoming/running/ended from
   start_at/end_at vs now. is_registered = user in ContestParticipant OR
   in a ContestTeamMember of any team in the contest (two set queries,
   unioned in Python).

Pagination: page >= 1, 1 <= size <= 100 via FastAPI Query(ge/le) -> 422
on violation; defaults page=1 size=20; page beyond range -> empty items
list with 200 (never 500); total via select(func.count()).

EAGER-LOADING / N+1
-------------------
The plan requires selectinload-style eager loading to avoid N+1. The
response items reference ONLY columns (no relationship objects are
serialized), so no relationship is ever lazy-loaded: the per-user state
is computed from one aggregate query per list, and the assignment
class/problem objects the plan mentions are not part of the response
shape and are never touched. Zero N+1 by construction; documented in the
module docstring.

SUPERSEDED ENDPOINTS (deviation from brief, documented)
-------------------------------------------------------
The pre-existing plain-list endpoints at the same paths (list_problems in
routes/problems.py, list_contests in routes/contests.py, list_assignments
in routes/assignments.py, todo 18) were REMOVED — they returned bare
lists and would have conflicted with the new paginated endpoints at the
same paths (FastAPI matches the first registered route; leaving them
would shadow the new ones or produce a wrong OpenAPI schema). The 4
existing tests in tests/test_api.py that asserted the old bare-list shape
were updated to the {items, page, size, total} envelope (test_list_problems,
test_list_contests, test_list_assignments_student_sees_own_class,
test_list_assignments_teacher_sees_own). No test cases were deleted or
replaced; only the response-shape assertions changed. This was REQUIRED
by the brief's own verification gate ("full pytest tests/ -q -> all
pre-existing tests still green") — the old shape and the new shape cannot
coexist at one path.
